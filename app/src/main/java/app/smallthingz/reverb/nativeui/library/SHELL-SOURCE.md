# Library shell presentation proposal

Source is released 0.1.2 commit `3e16f8ddb78dca15df4b436d34d330801ce83ffd`; exact source/dependency hashes and immutable reference copies are beside this document. These files are integrated into native-hosts-20261021 and are not yet compiled or natively qualified. The original proposal/reference copies remain in the ignored library-shell-proposal directory. No production route, operation backend, recording, preference, device or build was changed.

## Concrete components

- `ReverbLibraryToolbarView`: released FilesScreen selection toolbar and AppTopBar with no status-bar padding. The owner supplies selection/busy/alert state, callbacks and the existing predictive-back frame. It owns no selection or back dispatcher. The ordinary toolbar preserves the released 66dp/14dp/46dp/15dp/23dp geometry, Circle brand, exact palette and noise. The selected toolbar preserves 16dp insets, 48dp wrappers, weighted title, conditional action enablement and source transform equations. Branch lifetime follows the original source.
- `ReverbLibraryTextAction`: natural-width Material3 1.4.0 TextButton for Retry/Undo, with 58dp minimum width, 40dp visual minimum height, 48dp minimum touch target, individual 12dp horizontal/8dp vertical padding and labelLarge. It exposes the original paragraph for the shared semantics provider. It adds no timer or state owner.
- `ReverbLibraryStatusView`: only the loading, failed and empty branches. Caller selects the exact original branch, preserving the list branch during refresh. Empty uses the existing native vertical viewport and retained scroll state, not platform ScrollView. The supplied frame clock/scope/nested host must be the real screen owners; root must register this viewport's native input phases. Loading remains the pinned Material3 indeterminate animation,40dp with4dp stroke. Error is bodyMedium muted plus natural Retry. Empty is84dp/28dp corner/34dp glyph with released color and alpha.
- `ReverbLibraryUndoCard`: direct FeedbackCard(INFO) with no invented entrance, exit, timer or full-screen input shield. Caller retains the exact LibraryUndoNotice window and aggregate deletion/Undo backend, and places the card at BottomCenter with16dp horizontal/12dp vertical outer padding. Card source uses18dp corners, surfaceContainerHigh,2dp tonal elevation,16/8/8/8dp edges,8dp gap, weighted live-region bodyMedium message and Undo TextButton. Source tonal overlay applies only if supplied container equals surface.
- `loading-stroke-width.patch`: only makes the existing exact indeterminate leaf's stroke configurable with the unchanged2dp Incidents default. No keyframe or clock change. Integration applied only this small patch, avoiding replacement of unrelated owner changes.

## Ownership and binding

`ReverbViewEnvironment` is immutable per window configuration/theme generation. Rebind palette changes; recreate configured contexts for actual configuration changes exactly as the surrounding host already does. Paragraphs share its font resolver and Density object. Toolbar and natural-button leaves implement NativeClickPhaseHost for the source-style shared pointer dispatcher, preserve hover accessibility delivery, rebind input after detach/reattach and use actual enabled state. Source Surface(onClick) has no explicit Button role; native Surface actions remain View. Only Material TextButton advertises Button role. No synthetic concatenated labels were introduced.

Backend callback guards remain mandatory in their existing owners. No callback here independently deletes, refreshes, starts/stops playback, writes recordings, starts a trim, or resets any persisted state. Undo card intercepts only its own bounds.

## Review and remaining evidence

Bounded self-review compared original FilesScreen/AppTopBar/AppFeedback and pinned Material3 Surface/Button/progress/token source. Per-edge rounding, source branch disposal, density-specific icon recreation, software/hardware shape clip, disabled tint, inert Surface input shielding and reattachment rebinding were checked. The spinner patch passes git apply --check against the current frozen source. No build, host test or native render/interaction pass is claimed.

Root still owns full screen/pull-to-refresh/edge-dismiss integration, existing selection predictive clock, lifecycle/operation controllers and accessibility window provider registration. Actual native rendering, minimum-target routing, keyboard/hover behavior, large text/RTL and constrained-window geometry remain qualification work. The toolbar is the released custom Library/AppTopBar and must not be reused as though it were Settings' M3 CenterAlignedTopAppBar. No inline player or fine-seek controller is included in this proposal.

Apache-2.0 source-derived spinner behavior retains its existing copyright/license headers; nativeui/incidents/APACHE-2.0.txt is the integrated license destination. This proposal introduces no dependency.

Independent Settings owner review found a keyboard fallthrough defect in the first proposal: controller-declined repeated DOWN/unmatched UP could reach stock View click handling. The ignored TextAction and toolbar proposal now route activation keys exclusively through the source controller in onKeyDown/onKeyUp; other keys use the platform path. The failed initial design is retained here as an explicit review finding, not a native pass.

The reviewed normal toolbar is now extracted into `ReverbAppTopBarView`, shared by Library and the separate Home migration owner. It adds only released AppTopBar parameters: optional Back, explicit supplied status-bar inset and configurable barHeight default66dp. Noise covers the full status-plus-bar background. Library explicitly disables status-bar padding and keeps66dp. Shared topbar and all Library shell click leaves now take a mandatory nativeInputRoot so native wrapper ancestors cannot introduce an extra platform press delay. No Home production route/layout is changed by this extraction.

Root review records TextButton accessibility topology as remaining host wiring: the literal merged Role.Button/Text shape may need the same parent/role-only-child arrangement as OnboardingFooter. The current native visual parent class alone is not proof of native semantics parity; no labels were joined, and no native accessibility pass is claimed.

Root found an expanded-hit precedence defect in the initial topbar fallback dispatcher: an earlier near candidate could hide a later direct shape hit. The corrected dispatcher checks all placed eligible visuals using actual clipped46dp shape bounds, selects direct hits before near hits, and reuses nativeMinimumTouchDistance/NativePointerHitScore priority for expanded targets. Five unrun focused tests cover narrow overlap, circular clipped corners, closest/tied near targets and mouse exclusion. Shared-root phase routing remains the primary host path.
