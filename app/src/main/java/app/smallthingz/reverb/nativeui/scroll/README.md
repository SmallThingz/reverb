# Native vertical scroll proposal

This directory is outside every frozen source set. It contains executable Kotlin state, delta/fling, mutation ownership and overscroll code plus twenty-one focused test cases; none has been compiled, run, integrated or installed by this lane. It replaces no current ScrollView yet.

The reference is released v0.1.2 (3e16f8ddb78dca15df4b436d34d330801ce83ffd) and its pinned foundation/animation 1.11.2. MainActivity.kt:751 calls fillMaxSize().verticalScroll(scrollState, enabled=interactionEnabled) without a custom fling, reverse direction or overscroll factory. PROVENANCE.json hashes the actual extracted dependencies. The pinned source is retained under pinned/; Apache license is included.

## Concrete pieces

- NativeVerticalScrollState: ordinary fields replacing ScrollState's rendering state, including the fractional accumulator, unknown initial maximum, layout clamp, direction bookkeeping, and integer-only saver.
- NativeVerticalScrollEngine: synchronous source pre-scroll -> local scroll -> post-scroll composition. Physical finger down is positive; the non-reversed vertical state uses its negation. dispatchWithOverscroll wraps the nested chain only when forward/backward scrolling is possible.
- NativeVerticalFling: deterministic default-fling sampling using the pinned public DecayAnimation. Supply splineBasedDecay<Float>(Density(currentDensity)); there is no copied spline, OverScroller approximation or invented velocity threshold.
- NativeVerticalOverscroll: vertical-only adaptation of the released Android edge-effect path. API31+ uses the actual stretch RenderNode and negation effects; API28–30 uses the source glow compatibility behavior. It attaches to an existing host's drawing and observes pointer positions without consuming events.
- NativeEdgeEffectCompat: mechanically copied pinned source, changing only package and object name. The legacy opposite-release threshold, platform preview fallbacks and spline relaxation-distance arithmetic are preserved.
- NativeVerticalScrollOwner: one ordinary coroutine owner per real host. The retained state shares the pinned MutatorMutex, while each host supplies its actual frame clock, suspendable nested pre/post-fling chain and attachment state. No extra coroutine scope, gesture detector or scheduler is invented.
- NativeVerticalScrollOwnerTest: ten unexecuted ownership/continuation tests cover shared-page preemption, priority rejection, real versus local cancellation, partial nested consumption, zero-velocity terminals, suspended ancestor callbacks, captured key viewport and raw nested-scroll admission.
- NativeVerticalScrollEngineTest: eleven unexecuted state/consumption/ownership regression tests. They verify fractional reversals, bounds/re-measure, save/direction semantics, nested ordering, page-key admission, tiny/NaN velocity, blocked fling termination and reentrant cancellation.

No extra View, virtual layout tree, snapshot tree, or renderer framework is created. The lazy stretch RenderNode is specifically the released backend's workaround for Android stretch clipping/accumulation. It is not an optional substitute. Runtime math, callback and GPU costs are not claimed to be zero.

## Source contracts already represented

Scroll.kt:89–150 stores an integer position but carries fractional consumption separately. The source uses fastRoundToInt; this proposal calls that pinned utility rather than changing its half-tie/NaN behavior. Bounds changes clamp a position above the new maximum without resetting the fractional accumulator. Saving/recreating stores only the integer. Raw dispatch does not update the last-scroll direction flags; ordinary ScrollScope.scrollBy ignores NaN before doing so.

Scrollable.kt:805–836 dispatches nested pre-scroll, then the local reversed-axis scroll, then nested post-scroll. Overscroll wraps that whole chain. The scroll state is measured before child placement, and the ordinary non-reversed vertical child is placed at -value. Layout must remain in integer pixels, not a separately rounded animated translation.

Scrollable.kt:511–560 handles only PageUp/PageDown KeyDown without Ctrl: one immediate viewport-sized UserInput mutation. It is not a smooth-scroll command. Native focus navigation/bring-into-view is separate; do not accidentally introduce ScrollView's Home/End/Space policy as a replacement.

Scrollable.kt:1061–1108 admits a default fling only when abs(initialVelocity)>1f, including the source's NaN branch. It samples the pinned spline, computes delta=currentAnimationValue-lastValue, keeps the current animation velocity, and stops when abs(delta-consumed)>.5f. A local detached-node CancellationException retains current velocity and allows nested post-fling. Real job cancellation still propagates through the withContext/coroutineScope boundaries and does not guarantee a post-fling callback. The source explicitly forces motionDurationScale=1f for fling; reading ValueAnimator's scale would change its behavior. Float division then toLong is retained even for that fixed scale.

AndroidOverscroll.android.kt:539–685 catches a still-active stretch with a zero pull at a new scroll cycle, destretches before scrolling, and uses a 4x multiplier for fling/SideEffect relaxation. Only UserInput leftovers beyond half a pixel create a new pull. A fresh pull is deliberately not added to the returned scroll consumption. Resuming real scrolling releases an existing stretch.

AndroidOverscroll.android.kt:687–754 first absorbs an insufficient relaxing fling, then delegates the remaining velocity through nested pre/fling/post, then absorbs the final leftover and releases effects. NativeVerticalOverscroll.beginFling returns a context whose active bit preserves the source's initial empty-size decision; finishFling uses that same context. Do not skip finishFling for zero velocity.

The pointer observer follows the original pointer id while still pressed, then the first remaining pointer. It preserves the last horizontal displacement after all pointers are up so an existing effect does not jump to the center. It observes consumed events too, and does not own drag admission.

The API31 renderer reproduces the source 30 dp cross-axis expansion, rounding only the RenderNode width while translating by the exact float pixel elevation. It applies previous-stretch negation before current effects, records content in the enlarged node without changing content dimensions, and translates back when drawing the node. Unsupported software stretch finishes the edge effects and draws content normally. Legacy glow draws after content with the source zero default padding and bottom rotation/translation.

## Required executable host integration

The existing page geometry remains unchanged: viewport fills the page; content measures at bounded width/unbounded height; no added padding, scrollbar or fillViewport. Safe-area and24/20dp page padding remain outside this host.

The shell lane is preparing the shared Initial/Main/Final pointer arbiter in pager-host-proposal. This proposal deliberately does not add a second guessed MotionEvent drag recognizer. The arbiter supplies admitted vertical deltas and pinned VelocityTracker results, and must route the same consumed changes to ReverbClickController's Main/Final cancellation hooks. Parent interest uses the current gesture connection, not a universal scrollable-parent Boolean.

For an admitted drag, acquire the source-equivalent UserInput mutation owner, cancel a superseded lower-priority mutation through its terminal path, and call dispatchWithOverscroll. For a page key, acquire that same mutation priority and call pageKey, without wrapping the key delta in new overscroll. Do not use Android's minimum fling threshold or Android VelocityTracker in place of the pinned recognizer policy. The source excludes mouse dragging and has a separate indirect/trackpad route.

For a completed drag, keep the physical velocity sign and:
1. If state can scroll, call overscroll.beginFling(physicalVelocity); otherwise use the full velocity without an overscroll continuation.
2. Dispatch the enclosing parent's pre-fling and wait for its actual continuation/consumed result.
3. Run NativeVerticalFling with the negative remaining physical velocity. Each logical sample is negated into physical Y, dispatched with SideEffect overscroll/nested scrolling, then negated back for consumed delta.
4. Return current leftover velocity, negate it to physical, and complete nested post-fling.
5. Pass the final leftover to the matching overscroll.finishFling context.

Pre/post-fling is suspendable in the released implementation. It must not be replaced by synchronous zero-return placeholders merely because a current parent often consumes zero. NativeVerticalScrollOwner uses actual suspend functions for this chain, not callback generations or synchronous placeholder returns.

The host supplies its real MonotonicFrameClock to NativeVerticalScrollOwner; the clock must execute the sample inside the frame callback, not resume it later with a copied timestamp. The owner requests frames only while NativeVerticalFling is running. Overscroll retains its ordinary invalidation path. The mutation owner must preserve source priority/cancellation and asynchronous nesting; isScrollInProgress is not just isFlinging. startDragImmediately is active scroll mutation OR overscroll.isInProgress.

For rendering, clip the viewport using the source ClipScrollableContainer contract: main axis clipped, cross axis expanded by rounded30dp. Draw content at the exact negative integer state offset through overscroll.draw. Default factory glow color is0xff666666, not a new Material palette choice. No global theme/night/inversion settings change is involved.

## Lifetimes and current boundaries

MainActivity.kt:539–541 retains three ScrollState instances outside HorizontalPager. Keep one NativeVerticalScrollState per page across navigation; restoration does not reset other pages. HorizontalPager uses its default beyondViewportPageCount, so retention of state does not prove every offscreen scroll node stays alive. The native owner must retire a host at the same logical disposal boundary, not keep an old fling alive forever just because all three Views were prebuilt.

Predictive Back can build a second, noninteractive destination page using the same ScrollState. It shares the integer state but owns its own scroll node/overscroll drawable. Do not share mutable RenderNodes/EdgeEffects between those hosts. Hidden-but-still-owned hosts must not call overscroll.dispose just because window focus changed.

The current successor OnboardingVerticalScrollView remains explicitly unqualified until its owner wires this viewport. Outstanding integration work is exact shared drag arbitration/velocity feeding and host wiring, indirect/wheel input and actual frame-phase comparison. The local accessibility and focus paths below now have executable source-derived implementations. Enabling/disabling interaction resets input admission according to source; it is not by itself evidence that every already-running scroll animation should be forcibly stopped. An actual detached/discarded owner must release only its own callbacks and effects.

The Canvas/backend source mapping does not prove raster identity. The native host's real hardware Canvas dimensions, clip, transform and draw phase must be compared against the actual released verticalScroll on the connected Android device. Required finite comparison: fractional slow drag and reversal; drag-to-fling at both bounds; new touch catching a fling/stretch; multi-pointer transfer; pager-versus-vertical30° interest arbitration; row press cancellation; PageUp/Down; resize/reopen with each page's retained position; predictive preview sharing; API31 stretch replay/negation and software-path source behavior. No tolerance/color/time adjustment should conceal a mismatch.

No tests or device work was run by this lane. Parent source review found no concrete deviation in the earlier fractional-state/overscroll arithmetic and RenderNode transforms. That does not qualify actual rendering. The new mutation owner and its tests still await independent source review and execution.

## Exact mutation and terminal ownership

NativeVerticalScrollState.mutate wraps the pinned public MutatorMutex in the same coroutineScope/try/finally structure as DefaultScrollableState. One state, and therefore one mutex, belongs to each retained page; a predictive preview of that page cannot acquire a second independent mutation owner. isScrollInProgress becomes true only after admission, and becomes false when the admitted block exits. An equal or higher priority mutation cancels its predecessor; a lower-priority fling cannot displace an active UserInput drag. No extra snapshot state is introduced.

NativeVerticalScrollOwner.drag exposes a stable physical-Y NativeVerticalDragScope. The shared shell recognizer remains the sole pointer detector. Its event channel calls owner.drag { scrollBy(delta.y) }, then launches owner.onScrollStopped(velocity.y) in the actual node scope after the drag mutation releases. Pointer cancellation supplies zero velocity, as the released ScrollableNode does. Actual node disposal cancels its owned scope; it does not cancel an unrelated page's scope or persistent device work.

The default fling uses the existing sampler inside withContext(MotionDurationScale=1), requests the explicit frame clock while running, and catches CancellationException inside that context as the pinned source does. A source-local nonzero sample after detachment throws a CancellationException without cancelling the Job, so its sampled velocity reaches nested post-fling. A job cancelled by MutatorMutex, caller disposal, or a cancelled suspended ancestor callback remains cancelled; the surrounding withContext/coroutineScope propagates it. There is deliberately no NonCancellable/finally path that manufactures post-fling or overscroll release. The sampler's finally only retires its own transient animation.

The direct terminal is: optional overscroll begin -> suspend ancestor pre-fling -> Default mutation/fling -> suspend ancestor post-fling -> matching overscroll finish. Zero velocity still traverses this chain. Overscroll finish uses the same begin context and the actual post-fling remainder. The engine's nested post-scroll route is raw/local and suppressed during any active state mutation; nested post-fling uses the released isFlinging rule and runs only its local fling without duplicating the outer pre-fling/edge wrapper.

Page keys capture the viewport at event admission, return immediately, and launch one UserInput mutation per accepted key. They do not add overscroll, wait for animation completion, or sample a later resized viewport. The actual host decides whether the event is PageUp/PageDown before calling this method and retains ordinary focus semantics separately.

The owner has no private lifecycle scope or broad close/reset operation. The host must supply its exact node scope and actual attachment predicate. Shared retained positions still require the eventual page host to propagate position changes to every currently drawn consumer; the present per-host positionChanged callback is not itself proof of predictive-preview layout invalidation. Neither these host tests nor source-equivalent coroutine boundaries prove actual native frame phase.

## Concrete viewport

NativeVerticalViewport.kt replaces the mechanics of the existing OnboardingVerticalScrollView without using ScrollView or adding a second pointer detector. It owns exactly one content View and exposes the existing scroll owner plus a scope bound to the actual attached host. The root shell retains all hit-path and Initial/Main/Final gesture routing; it binds its vertical channel to inputScope after attachment and forwards the consumed or unconsumed local pointer stream to observePointer for edge displacement. On detach, only this host's scope, state observer and edge renderer retire. A reattached/recreated node must receive a new root input binding. Actual source disposal/lifetime mapping still requires integration qualification.

The viewport measures the child at the source width constraints and an unbounded maximum height. Source fillMaxSize preserves a minimum child height equal to a tight viewport height. Android MeasureSpec cannot express a minimum with an unbounded maximum in one spec, so the ordinary-View adapter conditionally remeasures a shorter child at the exact minimum. This is an explicit additional measure cost, not a zero-overhead claim. The current released onboarding Column has no vertical weights/height-dependent children, so top-aligned child geometry remains the same; another arbitrary content type is not automatically qualified by this observation. The own viewport height is the child's height capped at the finite incoming maximum; an infinite main-axis maximum fails just as source ScrollNode does. No extra padding, scrollbar or fillViewport policy is added.

Bounds publish before placement. Content is placed at logical Start and exact integer top=-state.value clamped to this host's local measured range. Subsequent state changes use offsetTopAndBottom, preserving descendant geometry rather than remeasuring all rows. Shared state has direct registered callbacks for every drawn actual/preview host; the callback array changes only on registration, so scrolling does not allocate a snapshot list each frame. The two additional unexecuted host-independent tests verify shared delivery and safe observer retirement. Saved state is the existing page state's integer, restored before the first layout; the View does not create a competing Android scroll-state saver.

ScrollableArea applies clipScrollableContainer outside its delegated overscroll renderer. NativeVerticalViewport reproduces that order with an expanded rectangle outline on hardware and the same rectangle clip on software, then overscroll around content drawing. Expansion is round(30dp) on left/right only; top/bottom are the actual viewport. Actual RenderNode/canvas dimensions and raster remain unqualified. The retained text-geometry mapper uses child.left/top minus ancestor.scrollX/Y, so this host's actual negative child top and zero native scrollY map correctly without a second offset. The separate semanticsViewport rectangle remains0..width/height, matching the actual clipping layer's semantic bounds; it deliberately does not inherit the drawing shadow expansion.

PageUp/PageDown bubble from the focused child to owner.pageKey and use the exact captured-viewport mutation path. The host adds no Space/Home/End/arrow scroll policy and no platform fling physics. interactionEnabled controls new key/pointer admission; the shared root must rebind/reset its router for an enabled-state transition, while ordinary pager motion must not disable the whole page. The viewport itself does not infer that disabling new input cancels every accepted fling.

Accessibility scroll actions and focused-child bring-into-view are concrete; no pending bridge or stock ScrollView fallback remains. Ordinary child semantics remain exposed. The direct source range/actions/class mapping and request ownership are described below. Indirect/wheel input and actual platform event/frame behavior remain unqualified; there is no implied blanket accessibility pass.

Viewport qualification still needs actual short/tall/zero-height content, tight/at-most finite measurement, RTL logical Start, odd-density cross-axis clip, shared predictive preview movement, resize range clamp, PageUp/PageDown with real focus, detach/rebind cancellation and hardware stretch/negation. This proposal was not compiled or exercised on a device. No production route, Home code, system settings or recordings were changed.

## Concrete semantics and focus

NativeVerticalAccessibility derives forward/backward/up/down action admission from the released Android accessibility delegate: signed viewport distance is admitted only when the current range can move, and a scroll action returns immediately after launching the source semantics mutation. The source still requests the full viewport when less distance remains; NativeVerticalScrollOwner.semanticsScrollBy returns actual consumption. It uses the pinned default spring and per-frame MotionDurationScale, Default mutation priority, nested UserInput dispatch and no overscroll. It retains the consumed-distance accumulator rather than pretending requested distance was consumed. Native ScrollView class/range payloads are exposed only while the source scroll action exists. Range and position changes notify the ordinary View accessibility path; global Compose 100ms batching and native event-frame phase are not claimed identical without device qualification.

NativeContentInViewOwner is the vertical non-reversed adaptation of pinned ContentInViewNode. NativeBringIntoViewRequestQueue and NativeUpdatableScrollAnimation retain the original queue arbitration and per-frame continuation behavior. Requests refresh actual bounds; nested requests share a source-priority queue, nonoverlapping requests retire older callers, user mutations preempt Default animation, and incomplete consumption cancels pending requests rather than looping forever. A viewport shrink tracks focus only when it was previously maximally visible and becomes clipped. Losing focus does not cancel an accepted request. Repeated requestChildFocus for the same descendant does not invent another focus entry. The source still reads BringIntoViewSpec.scrollAnimationSpec despite its deprecation; default phone and Leanback resolvers retain the pinned minimum-distance/pivot policies.

The viewport refreshes descendant matrices and actual positions without clipping or per-ancestor integer rounding. Source localRectOf translates the requested rectangle by the unclipped FULL descendant bounding box top-left; that specific rule is preserved. Local and ancestor responder requests run as separate child coroutines so normal parent cancellation does not cancel the independently accepted local request. An actual native ancestor implementing NativeBringIntoViewParent participates directly; the final Android boundary calls requestRectangleOnScreen with Float.toInt rectangle conversion and immediate=false. The shell must wire the real horizontal pager responder where source has one; an ordinary native parent is not evidence that horizontal focus relocation passed. No text-geometry ownership or extra scrollY offset is added.

Android MeasureSpec's conditional minimum-height remeasure and native accessibility delivery are explicit adaptation costs/boundaries. This implementation has no stock ScrollView physics, hidden default recognizer, composition, virtual View tree or snapshot state. It still uses pinned public animation/geometry/frame-clock utilities and MutatorMutex; that dependency is deliberate and is not a claim that the dependency graph is already Compose-free.

Thirteen new host tests (NativeContentInViewOwnerTest:10; NativeVerticalAccessibilityTest:3) cover request completion/replacement, user-priority cancellation, unconsumable bounds, disappearing descendants, focus resize, no-op requests, semantic partial consumption/scale0, and directional range admission. They are written but unexecuted by this lane. Existing21 engine/owner tests are preserved. No actual keyboard, accessibility service, frame cadence, overscroll raster or motion pass is inferred from these tests.

Pinned BringIntoViewRequestPriorityQueue contains the ascending range `requests.size - 1..i` inside its cancellation branch; this port preserves it literally rather than silently repairing released behavior. The ordinary nonoverlap tests cover the current non-null request path. An unusual null trailing request can therefore retain the same upstream edge behavior; it is not presented as a newly corrected product bug.
