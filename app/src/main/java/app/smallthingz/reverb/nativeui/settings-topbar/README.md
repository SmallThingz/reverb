# Native Settings CenterAlignedTopAppBar

Status: source implementation; no build, rendered, interaction or accessibility pass. Original SettingsScreen and pinned Compose oracle remain untouched.

This is the actual Settings small center-aligned Material3 1.4.0 bar, not the custom66dp Home/Library AppTopBar. It uses64dp minimum content height growing for multiline TitleLarge, the released Reverb title typography,4dp navigation/action wrapper padding,4dp title padding on both sides, full-bar centering corrected for action extents, source integer vertical division, and relative RTL placement. Text preserves default wrapping/Clip/unbounded lines; no new ellipsis or text.

The root supplies remaining physical horizontal/top insets from systemBars.union(displayCutout) after already-consumed insets. It must not pass IME or bottom insets, add a second status-bar pad, or attach another insets listener. NativeWindowInsetsBinding is available at the owning window boundary. Surface-colored fill and the unchanged0x5A17 noise cover the outer bar including insets; content clipping starts after inset padding. Both source container-color states are transparent, with no scrollBehavior: there is no visible container animation, shadow, elevation, or bar drag to synthesize.

SettingsTopBarBinding projects the existing controller state and passes its original callbacks. Navigation stays enabled (Back/Undo icon is selected by hasUnsavedChanges); the root retains Settings' Initial-pass consumption, focus-group entry gate and hideFromAccessibility while settingsInputReady is false. Done's enabled predicate independently checks changed/persisting/calibration/tile editor/pending duration. Its explicit glyph tint depends only on hasUnsavedChanges, including dark full-color disabled Done during pending operations. The callbacks still own navigation order, permission/readiness checks, saving continuation, focus release and backend state.

ReverbStandardIconButtonView is one direct standard IconButton leaf:48dp minimum layout, circular40dp action/indication container,24dp original source icon and a non-drawing role semantic child. It preserves inherited content/ripple color separately from an explicit icon tint. Navigation inherits onSurface; Done inherits onSurfaceVariant even though its Icon explicitly uses onSurface. There is no surface fill or outline to invent. The existing click controller handles input/lifecycle; normal View touch dispatch is not claimed as expanded-target routing. The owning shared phase root must insert the actual inner action node with circular clip and float48dp touch expansion, below the outer bar's empty pointer shield.

Accessibility uses the window's existing cursor and geometry, with mandatory actual source-node facts. For the inner40dp action those facts must include float48dp expanded touch bounds, separately from the role's visual40dp bounds and described24dp glyph. The source is a generic merging clickable parent, described Icon, then fake Button role. Exact child enumeration uses the updated shared helper. The native host must preserve content clip semantics and source visibility independently from presence/hidden state. No opaque semantic ID equivalence or TalkBack pass is claimed.

Five focused tests cover odd-width full-bar centering/RTL, asymmetric action correction, multiline height placement, inset union/subtraction and all Done-enabled predicates. They are written, not executed. Actual A/B must cover physical density Light/Dark, top/cutout insets, narrow/large-font title wrapping, Back↔Undo, pending disabled Done tint, key/hover/ripple and described icon semantics. Very short externally forced height and tiny width remain layout-edge qualification cases; no tolerance or screenshots were used to alter source geometry.
