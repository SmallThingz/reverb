# Native About window and motion proposal

Integrated native About window/motion component; production route remains unchanged. Build, native window/frame and interaction qualification remain pending. Original proposal/correction evidence is retained outside source.

`ReverbAboutDialog(anchor, appearance, onDismiss)` is a concrete ComponentDialog host for the already integrated About content. The owner calls `show()` once per About entry and `dismiss()` when removing that route. The owner must recreate it when source anchor or density changes, matching released Dialog remember keys. Appearance/closure updates are supported within that lifetime. Parent lifecycle STARTED gates frame scheduling; disposal cancels its one Choreographer callback and never redelivers navigation.

Window policy is adapted from the pinned UI1.11.2 AndroidDialog, with the original FloatingDialogWindowTheme resource retained. It preserves full width, top gravity, non-fitting decor, cutout/inset flags, inherited FLAG_SECURE, API-specific soft-input policy, transparent Window background, empty title, 8dp allocation-only zero-alpha outline, wrap-content→full-height measurement, centered child layout, inset and inset-animation adjustment, outside down/up ownership, Escape tracking and the source no-op cancel(). It does not use AlertDialog defaults or grant/request any platform permission.

Motion preserves the released distinction:
- Close, outside and Escape: IntOffset slide220ms in/190ms out and alpha160ms in/140ms out, default FastOutSlowIn easing. An interrupted tween switches to the same default spring as Transition, retaining sampled position/velocity and thresholds. Settled transitions start a fresh clock, so reading time cannot consume close motion.
- Predictive Back and ordinary Back through its enabled callback: progress controls the inner Surface translation and alpha; commitment continues to1 over round(220ms*(1-progress)), then invokes owner navigation directly. Cancellation returns to0 over160ms. Explicit close disables/reset this gesture owner.
- The outer visibility layer includes navigation padding; predictive translation uses the inner Surface height exactly as the source modifier order.

The proposal uses Compose animation-core's render-free TargetBasedAnimation math and original pure predictive duration helper; it creates no Compose rendering tree. One Choreographer callback drives both active channels and stops at idle. No ValueAnimator start-time approximation or arbitrary animation duration is substituted.

Ten focused unit-test proposals cover a delayed close after reading, interrupted close continuity, zero animation scale, predictive commit/cancel, explicit-close retirement keyboard Back, zero-duration immediate commitment, minimum1ms continuation and the pinned Animatable Float scale arithmetic. Tests have NOT run. Source/frame parity is NOT established by those tests: actual native Window composition, dispatch phases/rapid target changes, animated measurement/size changes, frame-clock lifecycle restart, accessibility tree, outside hits, system Back cancellation, insets/IME and underlying native scroll behavior remain unqualified. Independent review is pending; primitives owner declined because their authorized vertical-scroll task is active. Root owns integration/build/device qualification.

`SOURCE.json` pins the original app sources and upstream source members. AndroidX adaptations retain Apache2.0; project behavior remains under the repository's existing license. An earlier self-review caught and corrected a potential stale global clock after settled entry; it was corrected before this proposal handoff and was never integrated or run.

Root independent review found an extra-frame delay at predictive progress1; corrected committed() to return an immediate terminal result, consumed synchronously by the host. The existing duration helper retains at least1ms for any positive remaining distance. Source inspection also confirmed SuspendAnimation uses Long/Float division before toLong, while Transition uses Double division with roundToLong; the two proposal clocks now preserve those distinct operations. These are source corrections, not executed test evidence.
