# Native motion and gesture primitives

This module contains the small motion/gesture algorithm families used by Reverb's explicit Android View owners. It has no Compose runtime, Composition, Recomposer, Transition, modifier tree or Material dependency. Frame callbacks and state cells come from this module's native runtime; the existing app owners continue to determine layout, invalidation and animation lifetime.

The mathematical source reference is AndroidX animation-core/animation **1.11.2**, matching the prior resolved implementation. Retained source-derived files keep their Apache 2.0 notices. The selected families are scalar/vector spring, tween, snap, linear/eased keyframes, infinite repeat, decay, cubic easing root solving, Oklab color vectors, coroutine Animatable/AnimationState lifecycle, mutation priority and minimum bring-into-view distance. Unused arc/spline keyframes, finite repeat/composition families and composition APIs are omitted. Android fling retains the platform's ViewConfiguration friction and the original spline sampling math.

`Keyframes.kt` implements only the linear/eased path used by Reverb. It retains the source timestamp clamping, endpoint precedence, easing order and cached-vector velocity behavior. `CubicEasingMath.kt` contains only the scalar Bezier helpers that this path requires. Native state cells are direct values, with explicit View owners handling notifications; there is no snapshot machinery.

Qualification must compare actual compiled implementations. The first frozen core subset passed 76,380 exact raw-bit comparisons against the pinned binaries and 129 deterministic Animatable frame/state/cancellation trace events. This proves the exercised mathematical/lifecycle cases, not rendered pixels or native dispatch smoothness. Color, gesture-priority and actual Android fling probes are separate checks. The Android fling probe uses the real platform method; an SDK stub is not accepted as a native result.

The release/reference renderers live only in the reliability variant. Their mutable models retain the pinned Compose state/animation implementation in separately bound Legacy classes, while native renderers use this module. Read-only QA projections adapt observations without replacing either engine.
